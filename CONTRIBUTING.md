# Как участвовать в проекте

Короткие правила для всех, кто работает в репозитории. Их читают один раз — дальше они работают сами.

## Ветки

- Название: `student/<псевдоним>/<номер-задания>` — например `student/spacefox/task-01`.
- Каждое задание — своя ветка, созданная от свежего `main`.
- В `main` напрямую не пушим — это защищено правилами репозитория.
- После merge ветку можно удалить (и так хорошо, и вручную — тоже).

## Коммиты

- Одна строка, повелительное наклонение: `add card for spacefox`, `fix table in TEAM.md`.
- Можно писать по-русски: `добавить карточку spacefox`.
- Без «фикс», «update», «поменял» и точки в конце.
- Один коммит — одна идея. Лучше два маленьких, чем один огромный.

## Pull Request

- Один PR = одна задача.
- Заголовок — что сделано: `Добавить карточку spacefox`.
- Заполняй чек-лист из шаблона PR (он подставится сам).
- Попроси review у одноклассника: свой PR нельзя одобрять и мержить самому.

## Review (проверка чужой работы)

Смотри на четыре вещи:

1. Ветка названа по правилу.
2. Изменения по делу — ничего лишнего.
3. Нет личных данных и паролей.
4. Нет маркеров конфликта `<<<<<<<`.

Пиши уважительно: сначала что получилось хорошо, потом что поправить.

## Что нельзя

- Пушить в `main` напрямую.
- Делать force push (перезаписывать историю).
- Оставлять личные данные, пароли, токены и ключи.
- Мержить свой PR без чужого одобрения.

## Если что-то сломалось

Не удаляй ветку и не паникуй: git помнит всю историю.
Открой issue с шаблоном **«❓ Вопрос»** или спроси учителя.

## Вопросы и сдача

- Вопрос — шаблон **«❓ Вопрос»**.
- Готово задание — шаблон **«✅ Сдать задание»**.
- Сломалось — шаблон **«🐛 Сломалось»**.
