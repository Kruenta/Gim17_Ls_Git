# Задание 01. Первый совместный Pull Request

**Уровень:** новичок
**Время:** 25–30 минут
**Где работаем:** только в браузере, на сайте github.com
**Кто работает:** все ученики — в ОДНОМ общем репозитории

---

## 🎯 Цель

Понять, как несколько человек работают в одном репозитории и не мешают друг другу:

1. **Ветка** — моя личная копия для правок.
2. **Pull Request** — «проверьте мои изменения и добавьте в `main`».
3. **Review** — проверка работы одноклассником.
4. **Конфликт** — это нормально, его можно решить.

---

## 📜 Правила игры (главное!)

| Правило | Почему |
|---|---|
| В `main` **напрямую не пушим** | иначе сломаем работу всем |
| Одна задача = **одна ветка** = **один PR** | проще проверять |
| Ветку называем `student/<псевдоним>/<задача>` | понятно, чья это работа |
| Свой PR **сам не мержишь** | сначала review одноклассника |
| Перед началом работы — **обнови ветку** | чтобы не отстать от `main` |
| Маленький PR лучше большого | легче заметить ошибку |

## 🌿 Шаг 1. Мой первый PR (безопасно, без конфликтов)

### 1.1. Создай ветку

1. Открой репозиторий курса.
2. Нажми на выпадающий список веток (сейчас там `main`).
3. Введи имя: `student/<псевдоним>/task-01`
   Пример: `student/spacefox/task-01`
4. Нажми **Create branch: … from main**.

✅ Ты в своей ветке. `main` не тронут.

### 1.2. Создай свою карточку

1. В ветке зайди в папку `students/`.
2. **Add file → Create new file**.
3. Имя файла: `<псевдоним>.md`
   Пример: `spacefox.md`
4. Содержимое:

```markdown
# <псевдоним>

- Увлечение: ...
- Чему хочу научиться: ...
- Любимая книга: ...
```

⚠️ Без настоящего имени, школы, адреса, телефона и email.

5. Внизу — сообщение коммита: `add card for <псевдоним>`
6. **Commit changes** → выбери **Commit directly to the `student/...` branch**.

### 1.3. Открой Pull Request

1. GitHub покажет кнопку **Compare & pull request** — нажми её.
   Если кнопки нет: вкладка **Pull requests → New pull request**,
   base: `main`, compare: твоя ветка.
2. Заголовок: `Добавить карточку <псевдоним>`
3. Описание (по шаблону):

```text
## Что сделано
- Создан файл students/<псевдоним>.md

## Чек-лист
- [ ] Нет личных данных
- [ ] Ветка названа правильно
- [ ] Одна задача — один PR
```

4. **Create pull request**.

### 1.4. Review и merge

1. Попроси одноклассника оставить review (см. шаг 3).
2. После одобрения нажми **Merge pull request → Confirm merge**.
3. Нажми **Delete branch** — ветка больше не нужна.

---

## 🧨 Шаг 2. Общий файл и первый конфликт

Теперь все вместе правят **один файл** `students/TEAM.md`. Здесь и появится конфликт — специально.

### 2.1. Новая ветка

Создай ветку `student/<псевдоним>/task-02` **от свежего `main`**.

### 2.2. Добавь строку в таблицу `students/TEAM.md`

```markdown
| spacefox | рисование | @spacefox |
```

Коммит: `add <псевдоним> to team list`.

### 2.3. Открой PR и синхронизируйся

1. Открой Pull Request в `main`.
2. Если GitHub пишет **«This branch is out-of-date»** — нажми **Update branch**.
3. Если появилось **«Can’t automatically merge»** или кнопка **Resolve conflicts** — это конфликт. Он ожидаем!

### 2.4. Разреши конфликт в браузере

1. Нажми **Resolve conflicts**.
2. Ты увидишь такое:

```text
<<<<<<< student/spacefox/task-02
| spacefox | рисование | @spacefox |
=======
| pixelcat | музыка | @pixelcat |
>>>>>>> main
```

3. **Оставь обе строки**, убери только маркеры `<<<<<<<`, `=======`, `>>>>>>>`:

```markdown
| spacefox | рисование | @spacefox |
| pixelcat | музыка | @pixelcat |
```

4. Нажми **Mark as resolved → Commit merge**.
5. Вернись в PR и нажми **Merge pull request**.

✅ Конфликт решён. Все строки на месте, ничего не потеряно.

---

## 👀 Шаг 3. Проверь работу одноклассника

Review — обязательная часть. Нельзя мержить свой PR самому.

1. Открой вкладку **Pull requests**.
2. Выбери PR **не свой**.
3. Вкладка **Files changed** — посмотри, что изменилось.
4. Нажми **Review changes**:
   - **Comment** — если есть замечание;
   - **Approve** — если всё хорошо.
5. Напиши хотя бы одну полезную фразу, например:
   - «Ветка названа правильно 👍»
   - «Кажется, тут лишняя пустая строка»
   - «Добавь, пожалуйста, любимую книгу»

## ✅ Чек-лист сдачи

- [ ] Работал(а) в общей ветке `student/<псевдоним>/...`
- [ ] В `main` не пушил(а) напрямую
- [ ] Создана карточка `students/<псевдоним>.md`
- [ ] Открыт и смержен Pull Request №1
- [ ] Добавлена строка в `students/TEAM.md` через Pull Request №2
- [ ] Конфликт разрешён, обе строки сохранены
- [ ] Сделан review чужого PR (Approve или Comment)
- [ ] Нет личных данных и секретов
- [ ] Ветки после merge удалены

---

## 💡 Подсказки

- **Update branch** = «подтяни свежие изменения из `main` в свою ветку».
- **Конфликт** возникает, когда двое меняют одни и те же строки. Это не ошибка, а сигнал: «решите вместе».
- Маркеры `<<<<<<<`, `=======`, `>>>>>>>` — служебные. Их в файле остаться не должно.
- Если что-то пошло не так — не удаляй ветку и не паникуй. Спроси учителя: история коммитов всё помнит.
- Ветку удалять после merge — хорошая привычка, а не обязательное правило.

## 🌟 Дополнительно (по желанию)

- Оставь в чужом PR **Comment** с предложением улучшения.
- Создай issue `Обновить карточку <псевдоним>` и закрой его своим PR
  (в описании PR напиши `Closes #<номер>`).
- Добавь в свою карточку emoji — маленький PR только про это.
